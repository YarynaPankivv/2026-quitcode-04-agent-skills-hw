Спостереження:

  проєкту «прямо не охоплює експорт та імпорт JSON воркфлоу». Отже, спрацювала межа «Не для: …
  експорту/імпорту JSON воркфлоу» з `description`.
- n01 («вузол Code») і n02 («редактор n8n») згадують n8n, але скіл, як і задумано, не спрацював.

  він зробив, прочитавши код і `references/pitfalls.md`.

## Що змінили в `description`

Нічого: жодного промаху, тож немає підстав щось міняти. Зміна під тест без промахів була б
підгонкою під ці 12 запитів.

Обмеження тесту:

- **Кожен запит прогнано один раз.** Модель недетермінована: сесія, що зараз спрацювала, може колись
  не спрацювати. Для впевненості варто 3–5 повторів на запит.
- **Запити писала людина, яка знає `description`.** «Ні»-запити обрано на межах, які `description`
  називає прямо (вузол Code, редактор, JSON воркфлоу), тож вони перевіряють саме ці межі. Складніший
  набір — непрямі формулювання без слова «n8n» (наприклад, «зовнішній сервіс автоматизації повертає
  результат на наш ендпоінт»).
- **Прогони йшли в робочому репозиторії, де вже є `lib/n8n/client.ts` і колбек-роут.** Наявний код
  міг підштовхувати до скіла. У проєкті без n8n-коду результат може відрізнятися.
