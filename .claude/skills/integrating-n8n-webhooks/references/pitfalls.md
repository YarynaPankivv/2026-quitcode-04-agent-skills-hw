# Пастки: документація, чужі скіли, типові помилки

## Коли документація й код n8n розходяться

| Джерело каже | Насправді | Що робимо |
|---|---|---|
| Документація n8n: Immediately відповідає «Workflow got started» | Код n8n повертає `{"message":"Workflow was started"}` | Текст відповіді не парсимо — лише код статусу |
| Офіційний пакет n8n-скілів: Header Auth відхиляє з **401** | Код n8n (`Webhook/utils.ts`) — **403** «Authorization data is wrong!». 401 — для Basic Auth і JWT | 403 = неправильний/відсутній `x-n8n-token`; не повторюємо |
| Той самий пакет: секрет вузла Crypto не прив'язується до credential | Для Crypto v2 документація й код беруть Hmac Secret із Crypto credential | Секрет — у credential, не в полі вузла |
| Приклад вебхука в документації Next.js: токен у `?token=` у GET, порівняння `!==` | Той самий гайд попереджає: GET кешуються й потрапляють у журнали | Лише POST, токен у заголовку, підпис + `timingSafeEqual` |

## Помилки, які агенти роблять найчастіше

| Помилка | Наслідок | Правильно |
|---|---|---|
| `N8N_WEBHOOK_URL=…/webhook-test/…` у `.env.example` чи коді | Працює 120 с після «Listen», далі 404 — заявки мовчки губляться | Лише `/webhook`; тестовий — людина сама у `.env.local` |
| `await fetch(n8n)` у Server Action перед `return` | Форма чекає воркфлоу; на Cloud — 524 через 100 с; блокує наступні дії користувача | Запис → `after(() => triggerN8n(…))` → `{ status, id }` |
| `fetch` без `signal` | Зависла мережа тримає функцію до ліміту хостингу | `AbortSignal.timeout(10_000)` на кожну спробу |
| Код не дивиться на `response.status` | 403/404 виглядають як успіх | `response.ok`, 4xx — помилка без повторів |
| Повтор з новим `idempotency-key` | n8n запускає воркфлоу двічі | Ключ створюється разом із записом і живе з ним |
| `body: JSON.stringify(lead)` — весь рядок з бази | IP, user agent, нотатки, сирі дані форми йдуть стороннім | `data` — лише поля, які читає воркфлоу |
| `NEXT_PUBLIC_N8N_…` «щоб працювало на клієнті» | Токен у JS-бандлі кожного відвідувача | Виклик лише з сервера |
| `const body = await req.json()` у колбеку, потім підпис від `JSON.stringify(body)` | Байти змінюються — підпис не сходиться або (гірше) рахується від чужої серіалізації | `req.text()` → підпис → `JSON.parse(raw)` |
| `signature === expected` | Витік через час порівняння | Довжини + `crypto.timingSafeEqual` |
| Підпис без перевірки `x-n8n-timestamp` | Перехоплений колбек можна відтворити будь-коли | Вікно 300 с в обидва боки |
| Запис результату в `after()` | 2xx уже віддано, n8n не повторить, а запис упав — результат зник | Стан — до відповіді; в `after()` — лише листи/сповіщення |
| Ключ ідемпотентності «застовплено», потім 500, ключ не звільнено | Повтор n8n отримує `duplicate`, результат загублено | На помилці після кроку 6 — звільнити ключ |
| `console.log(body)` / `console.log(headers)` для дебагу | Персональні дані й підпис у журналах | Подія, код, тривалість, розмір, sha256, `x-correlation-id` |
| `export const runtime = "edge"` | Немає `node:crypto`; edge у Next.js 16 застарілий | Node.js runtime (за замовчуванням) |
| `GET` для вебхука чи колбека | Кешування, журнали проксі з query | Лише `POST` |
